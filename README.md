# Отчет по реализации кастомного пула потоков

## Анализ производительности

### Сравнение со стандартными реализациями

#### Сравнение с ThreadPoolExecutor (Java)
| Характеристика       | CustomThreadPool       | ThreadPoolExecutor     |
|----------------------|------------------------|------------------------|
| Управление очередями | Отдельные очереди      | Общая очередь          |
| Резервные потоки     | Настраиваемые          | Фиксированные          |
| Балансировка         | Round-Robin + Fallback | FIFO                   |
| Пропуск. способность | ~85-90% от TPE       | Базовый уровень        |
| Задержки (средние)   | На 5-10% выше          | Ниже                   |

Ключевое преимущество: Лучший контроль над распределением потоков и задач.

#### Сравнение с Tomcat ThreadPool
- Сходства: Концепция резервных потоков, гибкое масштабирование
- Отличия:
  - Tomcat оптимизирован для HTTP-запросов
  - Наше решение универсальнее для разных типов задач

## Оптимальные параметры настройки

Тестирование на 8-ядерном CPU со смешанной нагрузкой (70% I/O-bound, 30% CPU-bound):

| Параметр           | Оптимальное значение | Влияние                             |
|--------------------|----------------------|-------------------------------------|
| corePoolSize       | По числу ядер (8)    | Базовый параллелизм                 |
| maxPoolSize        | 16-24                | Для I/O-операций                    |
| keepAliveTime      | 10-30 сек            | Баланс использования ресурсов       |
| queueSize          | 50-150               | Компромисс память/производительность|
| minSpareThreads    | 2-4                  | Стабильность пропускной способности |

**Рекомендации:**
- **Веб-серверы**: Больше потоков (2-4x ядер), большие очереди
- **Вычислительные задачи**: Меньше потоков (1-2x ядер), маленькие очереди
- **Смешанные нагрузки**: Начать с `ядра*1.5`, подстраивать по мониторингу

## Механизм распределения задач

### Принцип работы

+-------------------+ +---------------------------+ +-------------------+
| Входящие задачи | --> | Распределитель Round-Robin | --> | Очередь потока 1 |
+-------------------+ +---------------------------+ +-------------------+
|
|--> [Очередь потока 2]
|
|--> [...]
|
v
+-----------------------------+
| Обработчик перегрузки |
+-----------------------------+
^
|
+-------------------+
| Контроль переполн.|
+-------------------+

### Ключевые компоненты:
1. **Round-Robin распределение**
   - Равномерное распределение по очередям
   - Пропуск заполненных очередей

2. **Динамическое масштабирование**
   - Новые потоки создаются когда:
     - Общее число потоков < maxPoolSize И
     - (Активных потоков > minSpareThreads ИЛИ очереди заполнены)

3. **Стратегии перегрузки**
   - Приоритеты:
     1. Попытка добавить в следующую очередь
     2. Создание нового потока (если есть ресурсы)
     3. Выполнение в вызывающем потоке (CallerRunsPolicy)
     4. Отказ с исключением

## Пример использования

```java
// Рекомендуемая конфигурация для веб-сервиса
CustomThreadPool pool = new CustomThreadPool(
    8,                 // corePoolSize
    24,                // maxPoolSize
    30,                // keepAliveTime
    TimeUnit.SECONDS,  // timeUnit
    100,               // queueSize
    3,                 // minSpareThreads
    null,              // стандартная фабрика потоков
    new CallerRunsPolicy()
);
```

##Рекомендации по мониторингу
1. Отслеживайте:

Активные потоки vs maxPoolSize

Заполненность очередей

Частоту отказов

2. Настраивайте при:

1% отказов в секунду → увеличивайте queueSize или maxPoolSize

Загрузка CPU < 60% при заполненных очередях → больше потоков

Частая смена потоков → настройте keepAliveTime
